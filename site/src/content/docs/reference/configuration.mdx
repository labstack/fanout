Fanout resolves built-in defaults followed by nonempty process environment
values. Every setting is listed under [Settings](/reference/settings/server),
grouped by the part of the product it belongs to.

Those pages and `.env.example` are generated from `internal/config` by
`cmd/fanout-docgen`. `just docs-generate-check` verifies that they match the
schema the binary uses.

## Where a value comes from

All settings are read once at startup and require a restart. An empty
environment value means unset and preserves the built-in default. Native
installs listen on `127.0.0.1:7520`; the image supplies `FANOUT_ADDR=:7520`
and `FANOUT_DATA_DIR=/var/lib/fanout/data`.

The binary reads only process environment. `.env.example` leaves every value
empty and documents types, defaults, and secret file forms in comments. For a
source checkout, copy it to ignored `.env` for personal settings and development
credentials. Build the binary, then use `just run`: Node's native `parseEnv`
loads optional `./.env`, and inherited environment values win, including empty
values. Values are never executed as shell code or interpolated. The binary
validates unknown names and types. Production deployments supply their own
environment values or managed secret mounts.

## Naming

Custom names use `FANOUT_` plus a clear name, adding the area only when it
clarifies. Vendor credentials and endpoints keep `ANTHROPIC_API_KEY`,
`ANTHROPIC_BASE_URL`, `OPENAI_API_KEY`, and `OPENAI_BASE_URL`.

`FANOUT_AI_PROVIDER` defaults to empty, disabling chat. Exactly `anthropic`
or `openai` enables chat and requires that provider's key. Only the selected
provider's endpoint is validated and used. Inherited credentials never select
a provider. `FANOUT_AI_MODEL` selects the model; unrelated vendor/tool settings
such as `ANTHROPIC_MODEL` and `OPENAI_MODEL` are ignored. See
[AI settings](/reference/settings/ai) for base URL meanings and the
[configuration upgrade table](/start/install#configuration-upgrades).

## Unknown names

Unknown `FANOUT_` names fail startup. Platform-injected service-discovery names
are tolerated, and unrelated names in shared vendor namespaces are ignored.
Errors name the relevant environment variable. Boolean, integer, and Go
duration values must parse as their declared types.

## Secrets

Every secret accepts either its value or its file path:

| Value variable | File path variable |
|---|---|
| `FANOUT_AUTH_CODE_SECRET` | `FANOUT_AUTH_CODE_SECRET_FILE` |
| `FANOUT_OIDC_CLIENT_SECRET` | `FANOUT_OIDC_CLIENT_SECRET_FILE` |
| `FANOUT_SMTP_PASSWORD` | `FANOUT_SMTP_PASSWORD_FILE` |
| `FANOUT_METRICS_TOKEN` | `FANOUT_METRICS_TOKEN_FILE` |
| `ANTHROPIC_API_KEY` | `ANTHROPIC_API_KEY_FILE` |
| `OPENAI_API_KEY` | `OPENAI_API_KEY_FILE` |

Setting both forms nonempty fails startup. File contents lose exactly one
trailing LF or CRLF; an empty result fails. Errors name variables and paths,
never contents. The deployment controls file access; Fanout performs no
file-mode check. Secrets are redacted from startup logs.

Use deployment environment injection, Docker/Compose secrets, Kubernetes
Secrets, or a private selected SOPS profile. This public repository ships no
operator profiles or recipients. See
[runtime secret delivery](https://github.com/labstack/fanout/blob/main/docs/operations.md#runtime-secret-delivery)
for examples.

## Validation

The whole configuration is validated before any listener opens. A value the
binary cannot accept stops startup. [First boot](/start/first-boot) lists what
is checked. The healthcheck command derives its probe from the listener and
TLS environment settings without validating unrelated settings or secrets.
