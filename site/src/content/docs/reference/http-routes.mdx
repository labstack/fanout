Every route below is served on `FANOUT_ADDR` (`127.0.0.1:7520` by default;
the image sets `:7520`).
OTLP shares this listener but uses its own handlers and ingest credential; see

## Conditional routes

The table includes every route the binary can register. These routes depend on
configuration:

- `/debug/pprof/*` — only when `FANOUT_PPROF_ENABLED` is true, which is
  **not** the default. Enabling it also turns on mutex and block sampling.
- `/mcp`, `/api/mcp`, `/api/auth/oauth/*`, `/oauth/*` and `/.well-known/*` — only when
  `FANOUT_MCP_ENABLED` is true, which **is** the default.
- `/api/agent/*` — only when `FANOUT_AI_PROVIDER` selects `anthropic` or
  `openai`, with that provider's required key. An empty provider disables chat.
- `/api/auth/oidc/start` and `/api/auth/oidc/callback` — only in
  `FANOUT_AUTH_MODE=oidc`.

Everything else is always registered. A path shown with `:name` or `*` is the
pattern Echo matches on, not a literal URL.

## Interface stability

The `/api/*` routes serve the browser client and can change without migration
paths. [MCP](/guides/connect-over-mcp) is the agent interface. OTLP ingest and
[operational endpoints](/reference/endpoints) have their own contracts.

Manage alert rules through the [HTTP API](/guides/set-up-alerts). Administrators
rotate ingest tokens on **Connect telemetry** or with
`POST /api/settings/ingest/token/rotate`.

## Errors

Application API errors, including unknown routes and wrong methods, return objects shaped like
`{"code":"bad_request","message":"Safe explanation"}`. Codes are stable
snake_case identifiers; clients branch on `code` rather than message text.
Invalid dashboard or panel specs also include `problems` with field paths,
messages and optional hints. Every error response uses `Cache-Control: no-store`;
HEAD errors have no body. Server failures return a short, safe message; the
underlying error is logged and never returned.

| 409 | `conflict` |
| 413 | `payload_too_large` |
| 415 | `unsupported_media_type` |
| 422 | `unprocessable` |
| 429 | `rate_limited` |
| 500 | `internal` |
| 502 | `bad_gateway` |
| 503 | `unavailable` |
| 504 | `timeout` |

Other 4xx statuses use `bad_request`; other 5xx statuses use `internal`.
Specific conditions use `already_current`, `dashboard_version_not_found`,
`dashboard_version_conflict`, `invalid_spec` and `last_active_administrator`.
Tool failures carry `error: {code, message}` inside the tool result.
Panel execution results keep their own status and error fields.
OAuth, OTLP/gRPC, MCP JSON-RPC and AG-UI run errors keep their protocol spelling.
Operational responses at `/healthz`, `/readyz` and `/metrics` keep their bodies.

## What the requirements mean

- **none** — reachable without a credential.
- **any signed-in user** — a session, but no particular capability.
- **protocol handshake** — the OAuth and MCP endpoints, which authenticate
  as part of their own protocol rather than through the middleware.
- **a named capability** — the caller's role must carry it.
- **or a service credential** — additionally reachable without a browser
  session, which is how a scraper reaches the metrics endpoint.

`Any` registers every HTTP method with the same authorization requirement.
`GET /*` serves the single-page application for browser paths. Unknown `/api/*`
and OTLP paths return errors.
