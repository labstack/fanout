import { Tabs, TabItem } from "@astrojs/starlight/components";

Fanout ships as a single binary and as a multi-architecture container image.
Neither needs anything else installed: there is no runtime, no database and no
collector to place first.

<Tabs>
  <TabItem label="Docker">

```sh
docker run -d --name fanout \
  -p 7520:7520 \
  -v fanout-data:/var/lib/fanout/data \
  -e FANOUT_AUTH_CODE_SECRET=$(openssl rand -hex 32) \
  labstack/fanout:latest
```

Images are published to Docker Hub as `labstack/fanout` and mirrored to GitHub
Container Registry as `ghcr.io/labstack/fanout`. The two carry the same digests;
pick whichever registry your hosts already pull from.

`FANOUT_AUTH_CODE_SECRET` is required in the default `local` auth mode and must
be at least 32 characters — the container refuses to start without it. It is the
only setting the command above adds; the image ships listener and data-directory
defaults of its own. Select `FANOUT_AI_PROVIDER=anthropic` with `ANTHROPIC_API_KEY`,
or `FANOUT_AI_PROVIDER=openai` with `OPENAI_API_KEY`, to enable the chat
investigator. Chat is optional and disabled when no provider is selected, even
with inherited vendor credentials or endpoints. Selecting a provider requires
its key at startup and validates only its endpoint.

:::caution[Use a named volume, or fix the ownership yourself]
The image is distroless and runs unprivileged as UID/GID 65532. A **named
volume**, as above, is set up correctly for you. A bind-mounted host directory
is not: `-v "$PWD/data:/var/lib/fanout/data"` fails to open its data directory
unless that directory is already writable by 65532.
:::

The image sets `FANOUT_ADDR=:7520` and `FANOUT_DATA_DIR=/var/lib/fanout/data`.
Native installs default to `127.0.0.1:7520`; set `FANOUT_ADDR=:7520` to accept
connections from other hosts.

  </TabItem>
  <TabItem label="Install script">

```sh
curl -fsSL https://raw.githubusercontent.com/labstack/fanout/main/scripts/install.sh | sh
```

It resolves the latest release, downloads `SHA256SUMS`, **verifies the archive
against it before extracting**, and installs to `/usr/local/bin` when that is
writable or `~/.local/bin` otherwise. Set `FANOUT_PREFIX` to choose the
directory, or `FANOUT_VERSION` to pin a tag instead of taking the latest.

Versions are CalVer — `v{YYYY.M}.{N}`, numbered from 0 within each month, so
`v2026.8.1` is the second release of August 2026.

  </TabItem>
  <TabItem label="Native binary">

Download the artifact for your platform from [GitHub
Releases](https://github.com/labstack/fanout/releases), make it executable, and
run it:

```sh
chmod +x fanout
export FANOUT_AUTH_CODE_SECRET=$(openssl rand -hex 32)
./fanout
```

  </TabItem>
</Tabs>

## Verify what you downloaded

The install script checks the archive for you. If you took one from the releases
page by hand, check it yourself — both the checksum and the build provenance:

```sh
sha256sum -c SHA256SUMS
gh attestation verify fanout_v2026.8.0_linux_amd64.tar.gz \
  --repo labstack/fanout
```

For containers, record or pin the digest the registry returns rather than
trusting a moving tag:

```sh
docker buildx imagetools inspect labstack/fanout:2026.8.0
```

Release images are multi-architecture for `linux/amd64` and `linux/arm64`, and
archives cover Linux and macOS on both. Every artifact is built on a native
runner, because DuckDB needs cgo.

| Image tag | Points at |
|---|---|
| `labstack/fanout:latest` | the newest release |
| `labstack/fanout:2026.8.0` | that exact release |
| `labstack/fanout:main` | the tip of `main` |
| `labstack/fanout:sha-<commit>` | one specific commit |

Every tag above also exists under `ghcr.io/labstack/fanout`.

Standalone signatures and SBOMs are deliberately not published yet — the
reasoning is in the repository's release contract.

## Configuration upgrades

Apply these deployment changes before restarting with the new binary or image.
Every setting requires a restart.

| Previous setup | Current setup |
|---|---|
| YAML configuration and `--config` | Configuration comes from built-in defaults and nonempty environment values. Set deployment environment variables for your settings. |
| A mount at `/etc/fanout/fanout.yaml` | The new image silently ignores this file. Transfer its settings to environment variables before upgrading. |
| `FANOUT_AI_API_KEY` and `FANOUT_AI_BASE_URL` | Use the selected provider's `ANTHROPIC_API_KEY` / `ANTHROPIC_BASE_URL` or `OPENAI_API_KEY` / `OPENAI_BASE_URL`. |
| Chat enabled by an inherited key | Set `FANOUT_AI_PROVIDER` to exactly `anthropic` or `openai` and supply its key. Empty disables chat. Model selection remains `FANOUT_AI_MODEL`. |
| OpenAI base without an API version | Include `/v1` in `OPENAI_BASE_URL`; Fanout appends `/responses`. Anthropic still appends `/v1/messages`. Both preserve gateway prefixes. |
| Native listener on all interfaces | Native default is `127.0.0.1:7520`. Set `FANOUT_ADDR=:7520` for remote access. The container image supplies `:7520`. |
| Tracked `.env` defaults | Only generated `.env.example` is tracked, with empty values. Personal `.env` is ignored; `just run` loads it optionally and inherited values win. |

Secrets also accept `<ENV>_FILE` paths for managed mounts. Set either the value
or the path, never both nonempty. See [runtime secret delivery](https://github.com/labstack/fanout/blob/main/docs/operations.md#runtime-secret-delivery).

## What an instance opens

| Port or path | Purpose | Native default |
|---|---|---|
| `7520` | Browser, API, chat, MCP, OTLP/gRPC and OTLP/HTTP | `127.0.0.1:7520`, loopback |
| `./data` | Telemetry, query state, users, sessions, dashboards, alerts and agent history | `./data` |

Every OTLP export requires the ingest token, including on the shared port.
Ingest rejects requests before setup completes. Read [authenticate
exporters](/start/send-telemetry) before pointing a service at the instance.

Exporters use the shared port `7520` or the public HTTPS origin. Every OTLP
export requires the ingest token. A private collector hostname can be entered
on **Connect telemetry** before copying its generated configuration.

Separate interface bindings are also removed. If the dashboard is public but
ingest must remain LAN-only, keep Fanout's backend port private and deny
`/v1`, `/v1/*`, and `/opentelemetry.proto.collector.*` on the public proxy.
Allow collectors through the private network or a restricted proxy route,
and verify that neither OTLP transport is reachable through the public origin.
One port simplifies deployment; it does not replace this access policy.
