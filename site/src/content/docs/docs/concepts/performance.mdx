On a Hetzner Cloud ccx33 (8 dedicated vCPUs, 32 GB RAM), with telemetrygen
on a separate ccx33 over a private network, Fanout v2026.11.0-alpha accepted
**507,311 mixed OpenTelemetry items/s** over **306.8 seconds**.
The composition was 61,571 spans, 224,112 log records and
221,628 metric points per second. The run measured ingest only. Reads under sustained ingest did not meet the read target and are tracked in [issue #419](https://github.com/labstack/fanout/issues/419).

## Setup and measurement

Both hosts were described as **Hetzner Cloud ccx33, fsn1, ubuntu-24.04**. The Fanout host
reported AMD EPYC-Milan Processor, 8 logical CPUs and
32,857,186,304 bytes of memory. telemetrygen v0.157.0 sent
plaintext OTLP/gRPC over the private network, using 1,000-item batches
and 8 workers per process.

The `publish` preset ran 1, 2, 4, 8, 16, 32 and 64 processes per signal
for traces, logs, metrics and mixed ingest, with 3 repetitions per point.
Accepted throughput is the change
in Fanout's `fanout_ingest_rows_total` counter over the measured scrape window.

The suite accepted **667.3 million items** in total: 145,879,781 spans,
265,470,588 log records and 255,924,526 metric points.

## Measured mixed ingest

The sustained phase ran for **306.8 seconds** at 64 processes per signal.
Fanout averaged **7.73 CPU cores** and reached **10.6 GiB peak RSS**.
The generator host averaged **7.93 of 8 CPU cores**.
The sustained phase is classified generator-limited.

| Signal | Accepted items/s |
|---|---:|
| Spans | 61,571 |
| Log records | 224,112 |
| Metric points | 221,628 |
| Mixed total | 507,311 |

telemetrygen keeps one trace export in flight per process, while log and
metric processes keep eight. Synthetic, highly compressible telemetrygen
payloads measure ingest capacity on this hardware.

## Reproduce

From the [fanout-bench](https://github.com/labstack/fanout-bench) repository:

```sh
FANOUT_BENCH_HCLOUD_SSH_KEY='<key>' scripts/hetzner.sh \
  --fanout-version v2026.11.0-alpha \
  --preset publish \
  --repeat 3 \
  --output results/publish-ingest-ccx33x2-v2026.11.0-alpha
```

Both VMs default to ccx33. The
[publishing guide](https://github.com/labstack/fanout-bench/blob/main/docs/publishing.md)
documents provisioning, the private network and artifact collection.

Regenerate the website's data from the completed run:

```sh
node site/scripts/benchmark-data.mjs report.json samples.jsonl EVIDENCE_URL
```

Update authored headline figures with the report; the site build checks them
against the data.
