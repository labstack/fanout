Fanout is alpha. User-facing contracts and storage formats can change without
migration paths. Every documentation page states one of these statuses:

| Marker | Meaning |
|---|---|
| `shipped` | Available with a settled contract. |
| `preview` | Available; the contract can change without a migration path. |
| `planned` | Designed but unavailable. |

`llms.txt` includes the status of every non-shipped page. A page covering several
capabilities uses `preview` if any of its contracts remain unsettled.

## Operating limits

- Namespaces filter queries. Anyone who can query an instance can query every namespace in it. Each instance is one trust domain; use separate instances for mutually untrusted teams. A namespace does not represent a user, organisation or tenant.
- **No horizontal scale.** Ingest, query and maintenance share one process and one machine.
- **Capacity depends on your workload.** Payload cardinality, query mix and disk determine capacity. The published benchmark measures one release, host and workload. [Measure your own hardware](/docs/concepts/performance).
- **No migration paths.** Fanout is pre-release. Storage-format changes may require a fresh data directory. Preserve backups before upgrading.

Keep a separate copy of data you need to retain.
