Fanout is one self-hosted binary for OpenTelemetry investigation. The same Go
process accepts OTLP/gRPC, stores telemetry on disk, runs deterministic queries
and alerts, serves an AG-UI investigator and dashboards, exposes MCP tools and
MCP Apps, and hosts the browser client.

The canonical shipped product contract lives in
[OpenSpec](https://github.com/labstack/fanout/tree/main/openspec/specs). This
page is the operator runbook.

## Install

### Docker

The default enables the session-protected browser MCP adapter required by rich
chat views. The remote `/mcp` endpoint is enabled at the same time and remains
OAuth-protected:

```sh
docker run -d --name fanout \
  -p 7520:7520 -p 4317:4317 \
  -v "$PWD/data:/var/lib/fanout/data" \
  -e AUTH_CODE_SECRET="$(openssl rand -hex 32)" \
  -e SMTP_HOST=smtp.example.com \
  -e SMTP_USER=fanout@example.com \
  -e SMTP_PASS=<smtp-password> \
  -e SMTP_FROM='Fanout <fanout@example.com>' \
  -e AI_API_KEY=<anthropic-or-openai-key> \
  ghcr.io/labstack/fanout:latest
```

| Port or path | Purpose |
|---|---|
| `7520` | HTTP browser, API, AG-UI, and optional MCP transport |
| `4317` | OTLP/gRPC ingest |
| `./data` | Telemetry, query state, users, sessions, dashboards, alerts, and agent history |

The image binds both listeners on all interfaces. The native binary defaults
OTLP to `127.0.0.1:4317`.

### Native binary

Download a platform artifact from
[GitHub Releases](https://github.com/labstack/fanout/releases), make it
executable, and run it with the same environment variables:

```sh
./fanout
```

The browser listens on `:7520`; persistent state defaults to `./data`.

## First boot

Fanout validates configuration before opening listeners. Every instance needs
an AI provider key because the AG-UI investigator is part of the runtime.

Local authentication additionally requires:

- `AUTH_CODE_SECRET` with at least 32 characters;
- `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`, and `SMTP_FROM`;
- a positive `SMTP_PORT` (default `587`).

When the control database has no users, Fanout prints a one-time setup token:

```sh
docker logs fanout 2>&1 | grep -A8 "FANOUT SETUP"
```

Open [http://localhost:7520](http://localhost:7520), create the first
administrator with that token,
and save the ingest token shown after setup. The setup token expires after one
hour and is cleared when setup succeeds. The raw ingest token is shown once;
Fanout stores only its hash.

Local login has no passwords. Active users receive short-lived email codes.
OIDC deployments use the provider flow described under
[Authentication](#authentication).

## Send telemetry

Fanout accepts traces, logs, and metrics through **OTLP/gRPC**. Native
OTLP/HTTP is not implemented; place an OpenTelemetry Collector in front when an
HTTP exporter is required.

### Authenticate exporters

The current ingest token works in either header form:

```text
x-fanout-ingest-token: fo_<token>
Authorization: Bearer fo_<token>
```

Browser cookies and MCP OAuth tokens are not ingest credentials. Missing or
invalid ingest credentials return gRPC `Unauthenticated`. `PUBLIC_INGEST=true`
is the only bypass and is intended solely for disposable demos.

### Configure an SDK

```sh
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4317
export OTEL_EXPORTER_OTLP_PROTOCOL=grpc
export OTEL_EXPORTER_OTLP_HEADERS=x-fanout-ingest-token=fo_<token>
export OTEL_SERVICE_NAME=checkout
export OTEL_RESOURCE_ATTRIBUTES=service.namespace=storefront
```

Use `https://` when Fanout or a reverse proxy terminates TLS.

### Configure a Collector

```yaml
exporters:
  otlp/fanout:
    endpoint: fanout.example.com:4317
    headers:
      x-fanout-ingest-token: fo_<token>

service:
  pipelines:
    traces:
      exporters: [otlp/fanout]
    logs:
      exporters: [otlp/fanout]
    metrics:
      exporters: [otlp/fanout]
```

Fanout reads `service.namespace` from each OTLP resource. Missing values use
`DEFAULT_NAMESPACE` (`default`). Namespaces scope telemetry queries; they are
not users, organizations, or authorization boundaries.

### TLS

Choose one production pattern:

- Terminate TLS at a trusted reverse proxy and forward HTTP plus gRPC to
  Fanout's private listeners.
- Set both `TLS_CERT_FILE` and `TLS_KEY_FILE` for direct TLS on both listeners.

Direct TLS has a TLS 1.3 minimum and requires HTTP/2 for gRPC. Setting only one
TLS file is a startup error. Configure `TRUSTED_PROXY_CIDRS` to the actual proxy
network before trusting forwarded client addresses; do not use broad private
address ranges.

## Use Fanout

The shipped browser has two primary areas:

- **Chat** streams AG-UI investigations, renders rich MCP App activity, and
  persists owner-scoped threads and runs. Threads can be searched, renamed, and
  deleted.
- **Dashboards** stores multiple named, owner-scoped canvases with shared time
  and namespace filters and a draggable twelve-column layout. The first visit
  creates a System overview dashboard.

Deterministic telemetry queries do not require a model call. Chat uses the same
standard MCP tool registry in process, so agent, HTTP, MCP, and dashboard
results share one typed query contract.

Fanout's five investigation domains are:

| Domain | Result |
|---|---|
| Overview | Service traffic, errors, latency, cross-signal counts, and health |
| Topology | Observed service dependencies and edge health |
| Performance | Activity, endpoints, heatmap, and period comparison |
| Trace | Exact or relevant trace, waterfall/flame data, and correlated logs |
| Logs | Filtered entries, severity histogram, and trace/span links |

Alerts, ingest settings, and user administration are currently HTTP APIs rather
than browser pages; future browser surfaces require their own product change.

## Alerts

The alert engine is enabled by default and evaluates persisted
[expr-lang](https://expr-lang.org) rules every `ALERT_EVAL_INTERVAL` seconds.
Rules can scope a service and can use current traffic, error rate, latency, log
count, anomaly/health scores, and baseline deltas. A namespace selector is
stored with each rule, but current evaluation uses instance-wide service
rollups and does not apply that selector.

An alert moves from **pending** to **firing** after `for_seconds`, then to
**resolved** when its expression becomes false. Cooldown and repeat intervals
control repeated delivery. Webhooks support custom headers, an optional payload
template, and optional resolve notifications; the alert records its latest
delivery status.

| Endpoint | Capability |
|---|---|
| `GET /api/alerts`, `GET /api/alerts/summary` | Read/filter alert state |
| `GET /api/rules` | List rules |
| `POST /api/rules` | Create and compile a rule |
| `PUT /api/rules/:id` | Replace and recompile a rule |
| `DELETE /api/rules/:id` | Delete a rule and its alerts |
| `POST /api/rules/:id/test` | Dry-run against current service evidence |

Viewers can read alert state and rules. Operators and administrators can manage
and test rules. With `ALERT_ENABLED=false`, reads return empty state and writes
report that alerts are unavailable. Resolved history is pruned after
`ALERT_HISTORY_DAYS`.

## MCP server

Fanout can expose a Streamable HTTP MCP server at `/mcp`. Remote MCP requires a
canonical public HTTPS resource URL ending in `/mcp`:

```sh
MCP_ENABLED=true
MCP_PUBLIC_URL=https://fanout.example.com/mcp
PUBLIC_URL=https://fanout.example.com
```

`MCP_PUBLIC_URL` drives protected-resource discovery and token audience
binding. It must match the address clients use. A localhost-only deployment
without trusted HTTPS should leave MCP disabled.

Remote clients use OAuth discovery, dynamic client registration, authorization
code with PKCE, short-lived audience-bound access tokens, and rotating refresh
tokens. The browser's same-origin `/api/mcp` adapter uses its validated browser
session; the public `/mcp` endpoint remains OAuth bearer-only.

```sh
claude mcp add fanout --transport http https://fanout.example.com/mcp
```

### MCP tools

| Tool | Behavior |
|---|---|
| `observability_overview` | Read-only system health overview |
| `service_topology` | Read-only dependency topology |
| `service_performance` | Read-only service or system performance |
| `trace_detail` | Read-only exact or relevant trace detail |
| `search_logs` | Read-only filtered log exploration |
| `dashboard_list` | List the authenticated owner's dashboards |
| `dashboard_get` | Read one owned dashboard |
| `dashboard_create` | Create a complete named dashboard |
| `dashboard_update` | Replace an explicitly selected dashboard design |

The five observability tools return summary text and structured content in
every host. Clients that negotiate the MCP Apps profile also receive the
matching portable React visualization. Dashboard tools require both
`fanout:read` and `fanout:dashboard`; ownership comes from the verified token,
never tool input.

## Authentication

### Roles

| Role | Capabilities |
|---|---|
| Viewer | Read telemetry and alert state, manage own dashboards, read ingest metadata |
| Operator | Viewer capabilities plus agent runs and alert management |
| Admin | Operator capabilities plus user/ingest management and protected operations |

Changing a user's email, role, or active state revokes their browser sessions.
Fanout also prevents removal or deactivation of the final active administrator.

### OIDC mode

Set `AUTH_MODE=oidc` plus:

- `OIDC_ISSUER_URL`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`;
- canonical HTTPS `PUBLIC_URL`;
- `OIDC_EMAIL_CLAIM` and `OIDC_EMAIL_VERIFICATION` policy;
- optional allowed groups/domains and role-mapping groups.

Just-in-time provisioning is off by default. Enabling it requires an explicit
allowed group or domain policy. Issuer-policy email verification likewise
requires an allow policy.

### Public demo modes

`PUBLIC_READ=true` creates a synthetic anonymous viewer only for explicitly
classified read-only routes. It does not authorize agent runs, mutations,
ingest, MCP consent, user management, or private metrics. `PUBLIC_INGEST` and
`METRICS_PUBLIC` are separate switches.

## Operate

### Data layout

Everything durable lives under `DATA_DIR`:

```text
data/
  telemetry/
    ducklake.sqlite
    parquet/
  query/
    catalog.duckdb
    tmp/
  control/
    fanout.sqlite
```

The control database contains users, sessions, settings, dashboards, alerts,
OAuth records, and agent history. Back up the complete data root, not selected
files.

### Health, metrics, and profiling

| Path | Behavior |
|---|---|
| `/healthz` | Process liveness |
| `/readyz`, `/api/health` | Dependency-aware readiness |
| `/-/metrics` | Prometheus metrics; bearer token or admin session unless public |
| `/debug/pprof/*` | Optional profiling; admin operations capability required |

Set `METRICS_TOKEN` for non-interactive private scraping. An authenticated
administrator can also inspect private metrics through a browser session. Only
on an appropriate network, `METRICS_PUBLIC=true` removes authentication.
Profiling routes do not exist unless `PPROF_ENABLED=true`.

### Backup and restore

1. Stop Fanout so no ingest flush or control write is in flight.
2. Copy the complete `DATA_DIR`.
3. Start Fanout again.

To restore, stop the target instance, place the backup at its configured data
root, and start a compatible or newer binary. Control migrations apply at boot.
Downgrades across migrations are not guaranteed, so back up before upgrading.

### Retention and performance

Fanout flushes accepted rows by interval or batch size, updates minute rollups,
merges small DuckLake files frequently, and performs full retention/cleanup
maintenance less often. `RETENTION_DAYS=0` keeps telemetry indefinitely.

DuckDB self-sizes by default. `DUCKDB_MEMORY`, `DUCKDB_THREADS`, and
`DUCKDB_MAX_CONNS` are constraints for shared or query-heavy hosts, not generic
performance recommendations. Use the repository's current load/soak tools to
measure a target deployment rather than relying on dated throughput figures.

## Environment reference

Fanout loads `.env` without replacing process variables, then loads
`.env.${ENV}` as an explicit profile override (`ENV=development` by default).

### Runtime and storage

| Variable | Default | Purpose |
|---|---|---|
| `HTTP_ADDR` | `:7520` | Browser, API, AG-UI, and MCP listener |
| `OTLP_GRPC_ADDR` | `127.0.0.1:4317` | Native-binary OTLP/gRPC bind address |
| `INGEST_ENDPOINT` | derived | External collector address shown after setup |
| `DATA_DIR` | `./data` | Durable instance root |
| `DEFAULT_NAMESPACE` | `default` | Fallback OTLP resource namespace |
| `FLUSH_SECONDS` | `15` | Time-based telemetry flush interval |
| `FLUSH_BATCH_SIZE` | `50000` | Row limit that triggers a flush |
| `ROLLUP_EVERY` | `60` | Rollup cadence in seconds |
| `RETENTION_DAYS` | `30` | Telemetry retention; `0` disables expiry |
| `DUCKLAKE_MAINTENANCE_EVERY_SECONDS` | `3600` | Full expire/cleanup cadence |
| `DUCKLAKE_MERGE_EVERY_SECONDS` | `60` | Adjacent-file merge cadence; `0` disables |
| `ROLLUP_SKIP_TO_LATEST` | `false` | Treat restored/preseeded history as already rolled up at boot |
| `DUCKDB_MEMORY` | self-sized | Optional DuckDB memory cap |
| `DUCKDB_THREADS` | self-sized | Optional query worker cap |
| `DUCKDB_MAX_CONNS` | `4` | Query connection-pool cap |

### Agent, MCP, and alerts

| Variable | Default | Purpose |
|---|---|---|
| `AI_PROVIDER` | `anthropic` | `anthropic` or `openai` |
| `AI_API_KEY` | required | Provider credential |
| `AI_MODEL` | provider default | Optional model override |
| `AI_BASE_URL` | provider default | Optional compatible gateway |
| `MCP_ENABLED` | `true` | Serve remote and browser MCP transports |
| `MCP_PUBLIC_URL` | `https://demo.fanout.test/mcp` | Canonical HTTPS MCP resource/audience |
| `ALERT_ENABLED` | `true` | Run the alert engine |
| `ALERT_EVAL_INTERVAL` | `30` | Evaluation cadence in seconds |
| `ALERT_HISTORY_DAYS` | `7` | Resolved-alert retention |

### Authentication and network security

| Variable | Default | Purpose |
|---|---|---|
| `AUTH_MODE` | `local` | `local` email codes or `oidc` |
| `AUTH_CODE_SECRET` | local required | Email-code HMAC key, at least 32 characters |
| `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` | local required | Verification-code delivery |
| `SMTP_PORT` | `587` | SMTP port |
| `SESSION_IDLE_TTL` | `12h` | Browser-session idle lifetime |
| `SESSION_ABSOLUTE_TTL` | `168h` | Browser-session absolute lifetime |
| `PUBLIC_URL` | none | Canonical external HTTPS origin |
| `PUBLIC_READ` | `false` | Anonymous classified telemetry reads only |
| `PUBLIC_INGEST` | `false` | Disable OTLP authentication; demo-only |
| `METRICS_TOKEN` | none | Bearer credential for private metrics |
| `METRICS_PUBLIC` | `false` | Make Prometheus metrics public |
| `PPROF_ENABLED` | `false` | Register admin-only profiling routes |
| `TRUSTED_PROXY_CIDRS` | none | Proxies allowed to set forwarded client IP |
| `TLS_CERT_FILE`, `TLS_KEY_FILE` | none | Complete direct-TLS pair |

OIDC-specific settings are `OIDC_ISSUER_URL`, `OIDC_CLIENT_ID`,
`OIDC_CLIENT_SECRET`, `OIDC_EMAIL_CLAIM`, `OIDC_EMAIL_VERIFICATION`,
`OIDC_AUTO_PROVISION`, `OIDC_ALLOWED_GROUPS`, `OIDC_ALLOWED_DOMAINS`,
`OIDC_DEFAULT_ROLE`, `OIDC_OPERATOR_GROUPS`, and `OIDC_ADMIN_GROUPS`.

## Troubleshooting

- **Startup exits immediately:** inspect the first configuration error. Common
  causes are a missing AI key, incomplete local SMTP fields, a short code
  secret, an unusable MCP public URL, or half a TLS pair.
- **No telemetry appears:** verify OTLP/gRPC rather than HTTP, the token header,
  `service.namespace`, listener reachability, and the flush interval.
- **Remote MCP authentication loops:** make the client URL and
  `MCP_PUBLIC_URL` identical, use HTTPS, and configure the reverse proxy and
  `PUBLIC_URL` consistently.
- **Email codes do not arrive:** verify SMTP host, port, credentials, sender,
  and provider TLS requirements.
- **Queries slow down:** check readiness and rollup freshness, then measure the
  target host before changing DuckDB memory, threads, or connection limits.
